# Jörmund — Systems Reference

A technical reference for every implemented gameplay system in the current build. For lore, see `STORY_BIBLE.md`. For balance tuning, see `BALANCE_NOTES.md`. For boss design, see `BOSS_ROSTER.md`. For creature descriptions, see `BESTIARY.md`.

---

## 1. Core Loop

Jörmund is a top-down action RPG with roguelite meta-progression. The player explores a procedurally laid-out overworld, fights through hand-designed room encounters, clears dungeons, defeats bosses, and progresses through a four-act story structured around cardinal arches (South → West → North → Center).

**On death:** the player respawns at their last activated arch. Inventory, equipment, and runes are lost. Soul currency, kennings (earned titles), story flags, quest progress, and arch activations persist. The world layout regenerates from the same seed, but enemy spawns and loot rolls refresh.

**On run completion:** the player reaches the center of the island, confronts the Tyrant King, and makes a final choice.

## 2. Combat

### Movement and aiming

Eight-directional movement via WASD/stick, mouse aim for attacks and projectiles. The player faces the cursor at all times during combat.

### Dash

The primary defensive tool. Grants i-frames for the full dash duration (0.14s at 600 speed). Base 1 charge, refills when the cooldown (0.55s) completes. A perfect dodge (dashing through an attack at the last moment) refunds a portion of the cooldown. Runes can add extra dash charges and reduce cooldown.

There is no stamina bar. The dash is the entire defensive vocabulary — adding stamina would change the genre from action to resource management.

### Attacks

The player attacks with the currently active weapon. Melee weapons swing in an arc around the player; ranged weapons fire projectiles toward the cursor. Each weapon has a cooldown between attacks. Damage is computed as: `base_damage × difficulty_multiplier × kenning_multipliers × status_multipliers × armor_multipliers`.

### Shields and blocking

Some weapons are shields (ShieldWeapon). Holding the shield input raises a shield zone in the aim direction. Blocked hits are reduced by the shield's block percentage. Shields do not grant i-frames — they reduce damage, not eliminate it.

### Parrying

Attacks with a yellow telegraph are parryable. Timing a parry correctly (within the parry window) staggers the attacker and opens them for punishment. The red-flash telegraph means the attack is live and will deal damage. This yellow-warning → red-strike palette is the game's universal combat language and must never be broken — an unparryable attack must use a different color, not red.

### Status effects

Weapons can apply status effects on hit via StatusApplication resources (effect + chance). Active effects are tracked per-entity by StatusEffectComponent and compose multiplicatively. Current effects include burn (fire DoT), freeze (slow), poison (stacking DoT), shock (brief stun), and various boss-specific bindings (net, drag, snare).

### Enemy detection: smell and noise

Enemies detect the player via two senses:

**Noise** is transient — generated by movement, attacks, and weapon swings. Decays over time. Each enemy has a `noise_sensitivity` threshold; when the player's noise exceeds it within detection range, the enemy aggroes. Heavy armor increases noise generation.

**Smell** is persistent — builds during combat (the player's red blood stands out among the black-blooded dead). Decays slowly out of combat. Enemies with high `smell_sensitivity` will track the player from further away. This creates a stealth-vs-aggression tension: fighting generates smell that draws more fights.

Both values are displayed on the HUD as bars.

## 3. Weapons

### Slot system

The player has four weapon slots organized as two sets:

- **Active set:** primary + secondary (these are the weapons currently in hand)
- **Prepared set:** prepared_primary + prepared_secondary (stowed, ready to swap)

Pressing Q swaps the active and prepared sets. The swap takes 1.25 seconds (reduced by Swap Speed runes), during which the player is in the SWAPPING state and cannot attack. This is a deliberate commitment — swapping mid-fight is a tactical decision with a vulnerability window, not an instant toggle.

Two-handed weapons occupy both slots in a set (primary + secondary). Equipping a two-handed weapon requires both slots to be empty.

### Weapon types

Weapons extend the base `Weapon` class. Each has: `base_damage`, `cooldown`, `element` (physical/fire/ice/lightning/poison/holy/dark), `knockback`, `on_hit_effects` (status applications), and `wielder_speed_multiplier` (heavy weapons slow you).

Subtypes include `MeleeWeapon` (swing arc, hitbox), `RangedWeapon` (projectile speed, count, spread, pierce), and `ShieldWeapon` (block percentage, block arc).

### Elements

Seven elements exist: Physical (0), Fire (1), Ice (2), Lightning (3), Poison (4), Holy (5), Dark (6). Element affects damage color, status effect chance, and interacts with per-element resistance on armor and kennings.

## 4. Armor

Three slots: Helmet, Chest, Boots. Each piece can modify:

- `damage_reduction` — flat subtraction from incoming damage (applied after multipliers)
- `damage_taken_multiplier` — percentage resistance (0.85 = 15% resist)
- `element_multipliers` — per-element resistance (keyed by Element enum)
- `melee_damage_multiplier` / `ranged_damage_multiplier` — offensive bonuses
- `move_speed_multiplier` — heavy armor slows, light armor doesn't
- `max_health_bonus` — flat HP increase
- `noise_weight` — per-second noise added while moving (leather ~3, mail ~8, plate ~15)

Armor damage is floored at 1 — a hit that physically connects always deals at least 1 damage. This prevents extreme armor stacking from making the player invulnerable to chip damage, which would flatten the difficulty curve and break the feedback contract (every connect should register).

## 5. Rune System

Runes are the per-run build system. Each rune is a RunestoneItem bearing a passive stat bonus. When collected, runes accumulate in a separate rune collection (not the main inventory) and their bonuses stack additively.

### Identity

Each rune has two axes:

- **Letter** (one of 24 Elder Futhark symbols: Fehu, Uruz, Thurisaz, ...) — determines which stat the rune boosts
- **Conduit** (Slate, Bone, Wood, Gold) — determines the magnitude of the bonus and which act the rune can appear in

This creates 96 unique rune types (24 letters × 4 conduits).

### Stats

Runes can boost 17 different stats:

| Stat | Type | Example |
|---|---|---|
| Melee Damage | % | +3% per rune |
| Projectile Damage | % | +3% per rune |
| All Damage | % | +2% per rune |
| Damage Resistance | % | +2% per rune |
| Fire/Ice/Lightning/Poison Resist | % | +5% per rune |
| Move Speed | % | +2% per rune |
| Max HP | % | +3% per rune |
| Shield Effectiveness | % | +3% per rune |
| Melee Weapon Size | % | +5% per rune (hitbox scale) |
| Dash Charges | flat | +1 extra dash |
| Swap Speed | % | +10% faster weapon swap |
| Dash Cooldown | % | +5% shorter cooldown |
| Projectile Speed | % | +3% per rune |
| Rune Rerolls | flat | +1 reroll per run |

### Conduit tiers

| Conduit | Act | Bonus magnitude | Drop rarity |
|---|---|---|---|
| Slate | Act 1 | Lowest | Common |
| Bone | Act 1 | Low | Common |
| Wood | Act 2 | Medium | Uncommon |
| Gold | Act 3 | Highest | Rare |

### Crafting

Runes are craftable at fortune-teller NPC stations using a Bone Tablet (conduit material) plus reagent items. Each letter × conduit combination has a dedicated recipe .tres file.

## 6. Kenning System

Kennings are Norse-style compound titles that serve as the meta-progression system — permanent unlocks that persist across deaths and runs.

### Structure

Each kenning is a Kenning resource with:

- **Identity:** display_name (the title itself, e.g. "Bone-King's-Bane"), epithet, description, flavor text, category (Offense/Defense/Elemental/Mobility/Utility)
- **Unlock:** gated by a story_flag (boss kills, quest completion, arch activation, or custom flags). Some kennings are hidden when locked (boss kennings, to avoid spoilers).
- **Effects:** broad damage multipliers, per-element damage/resistance multipliers, move speed, dash cooldown, max HP bonus, binding immunity
- **Conditions:** some kennings only activate below/above a health threshold (clutch kennings)
- **Tradeoffs:** some kennings have both positive and negative modifiers (e.g. +25% damage dealt, +15% damage taken)

### Loadout

Up to 4 kennings can be equipped at once. The loadout persists in GameState across deaths. All equipped kenning multipliers compose multiplicatively — the same math as StatusEffectComponent.

### Current catalog (22 kennings)

Kennings range from starter titles (unlocked from the start) to boss drops (hidden until earned). Examples:

- **Bone-King's-Bane** — +18% damage dealt (boss drop: Skeleton King)
- **Ash-Walker** — immune to fire damage (boss drop: Cinder Sovereign)
- **Net-Cutter** — immune to all binding effects and pull impulses (boss drop: Drowned Crone)
- **Noose-Breaker** — +15% move speed while at or below 50% health (boss drop: Galgi)
- **Iron-Sided** — +15% damage resistance, -10% move speed (tradeoff, quest unlock)
- **Mead-Hall-Sated** — +25 max HP (quest unlock)

## 7. Soul Currency

Souls are the universal currency. Earned by killing enemies (each drops `currency_drop_min` to `currency_drop_max` souls) and as quest rewards.

**Persistence:** soul currency lives in GameState and persists across deaths. This is the one resource the player keeps when they die — it creates a "progress ratchet" where even a failed run that earned 200 souls lets the player buy something on the next attempt.

**Uses:**

- **Crafting:** every recipe has a `currency_cost` in souls (8 for basic consumables, 10–15 for mid-tier, higher for weapons/armor)
- **Buying:** shop NPCs sell reagent items for souls (Bone Tablet 10, Hollow Bone 14, Living Fire 20, etc.)
- **Quest turn-ins:** some SOUL-type quests require paying souls as an objective

## 8. Consumables

Two families of consumables exist:

### Tradeoff consumables (existing)

These grant powerful buffs with corresponding penalties:

| Consumable | Buff | Penalty | Duration |
|---|---|---|---|
| Fen Poultice | +25% damage dealt | -10% move speed | 15s |
| Mountain Marrow | +15% damage dealt | +10% damage taken | 25s |
| Brine Tonic | -40% damage taken | -20% move speed | 8s |
| Frostbloom Draught | +30% speed, +10% damage | none (short) | 12s |
| Pyre Salve | Clears all hostile statuses | none | instant |

### Pure-buff consumables (tiered system)

Three consumable lines with no drawbacks, designed for sustained use:

| Line | T1 effect | T2 Strong | T2 Long | Duration |
|---|---|---|---|---|
| Ember Broth (HoT) | 2 HP / 2s | 3 HP / 2s | 2 HP / 2s | 1 / 1 / 2 min |
| Windrunner Tonic | +10% speed | +20% speed | +10% speed | 1 / 1 / 2 min |
| Stone Draught | -10% damage taken | -20% taken | -10% taken | 1 / 1 / 2 min |

The tiered system branches at each upgrade: choose stronger effect OR longer duration. T3 (strongest, longest, or balanced) is defined but has no recipes yet.

Only one of each consumable type can be active at a time (same effect_id = REFRESH stacking). All types can be active simultaneously.

**Usage:** double-click from inventory. Applies a StatusEffect via the existing status pipeline. The HoT line uses a `heal_per_tick` field on StatusEffect with a `tick_heal` signal routed through the player to HealthComponent.

## 9. Crafting

Crafting happens at NPC stations in towns. Each NPC has a `station_name` and a list of `Recipe` resources they can craft.

### Recipe structure

Each recipe specifies:
- `inputs` — array of ItemQuantity (item resource + count needed)
- `requires_weapon` — optional weapon that must be equipped/provided (for weapon upgrades)
- `currency_cost` — soul cost
- `output_item` / `output_weapon` — what gets produced

### Stations

NPCs in the three towns (Wickbarrow, Storsprunga, Nasus) serve as crafting stations. The fortune tellers specifically handle rune crafting. Other NPCs handle weapons, armor, and consumables.

## 10. World Generation

### PathManager

The entire world layout is driven by PathManager, an autoload that builds the scene graph at runtime from data tables. No placement decisions happen outside PathManager. The system has four layers:

**POOL_DEFS** — maps pool IDs to scene directories. Each pool contains buffer scenes (2-exit corridors), cross scenes (3-4 exit intersections), and clearing scenes (1-exit dead-end reward rooms).

**CHAIN_DEFS** — ordered array of chain definitions. Each chain specifies: start scene, end scene, pool, length, anchor position, directional constraints, and endpoint behavior. Chains generate in order; later chains can anchor on earlier chains' resolved endpoints.

**Scene scanning** — at startup, PathManager scans every pool directory, reads each .tscn file's exit nodes (ExitNorth/South/East/West), and catalogs them by exit combination.

**Chain generation** — for each chain, the generator walks from the start scene toward a target cell, placing buffer scenes whose exits match the needed entry direction. Multi-exit scenes consume clearings from the pool for their side exits. If no valid candidate exists, the chain ends early.

### Key constraints

- `chain_axis` — locks a chain to horizontal or vertical movement only
- `reserved_approach_dirs` — prevents a chain from approaching its endpoint from a specific direction (preserves that face for a sibling chain)
- `final_forward_dir` — forces the last step to arrive from a specific direction
- Clearings are consumed per side exit — pools need enough clearings in each direction to support their cross scenes

### Current pools (15)

north, east, westmoor, coast, coast_west, eastreach, sprekken_approach, sprekken, sundust, deep_desert, hollowmere, hrimbjarg, thursdal, myrkfen, garnvik, hindarfjall, brann

## 11. Persistence and Save System

### Three save slots

Stored at `user://save_slot_<N>.cfg` as ConfigFile. Per-save difficulty (Easy/Normal/Hard) is chosen at New Game and locked for the save's lifetime.

### What persists across death (GameState)

- Soul currency
- Death count
- Story flags (arch activations, boss kills, quest state, kenning unlocks)
- Last activated arch (respawn point)
- World seed
- Kenning loadout (which 4 are equipped)

### What resets on death (RunState)

- Inventory (all items lost)
- Equipment (weapons, armor)
- Rune collection
- HP (refilled to max)
- Status effects (cleared)
- Smell/noise (reset to 0)

### Auto-save triggers

1. Scene transition (every room change)
2. Arch awakening (explicit progress checkpoint)
3. Death respawn (with incremented death count — can't escape death by quitting)

## 12. Difficulty System

Difficulty scales enemy behavior, not player power. The player's damage, cooldowns, dash, and movement are identical across all three modes.

| Knob | Easy | Normal | Hard |
|---|---|---|---|
| Enemy HP | 0.7× | 1.0× | 1.3× |
| Enemy damage | 0.7× | 1.0× | 1.3× |
| Enemy movement | 0.8× | 1.0× | 1.2× |
| Enemy projectile speed | 0.8× | 1.0× | 1.2× |
| Player regen | 2 HP/s up to 50% max | none | none |

Easy mode's passive regen pauses during combat and caps at 50% — it's a floor, not a ceiling.

## 13. Towns and NPCs

Three settlements exist on the island:

**Wickbarrow** — the starting town south of the island. Home to the Observer (lore), Aud the bath-keeper, Verðandi (the fortune teller, secretly a Norn), and various crafting NPCs. The player spawns at the South Arch near Wickbarrow.

**Storsprunga** — western coastal town. Home to Ylla (fortune teller, mortal practitioner), and coastal-themed crafting NPCs.

**Nasus** — northern walled city. The largest settlement. Home to Svala (fortune teller, mortal practitioner), and high-tier crafting NPCs.

NPCs are data-driven: each has a `dialogue` resource, optional `sprite_name` for sheet-sprite rendering, and optional crafting station with recipes. Interaction is proximity-based (enter the NPC's area → press E).

## 14. Quest System

Managed by QuestManager autoload. Four quest types:

- **STORY** — narrative quests that complete via story flags. Can be gated on boss kills via the `target_boss` field (matched against the boss_name passed to `_on_boss_defeated`).
- **SLAYER** — kill N of enemy type X. Tracked by enemy scene path.
- **COLLECT** — gather N of item X. Tracked by item resource path.
- **SOUL** — pay soul currency + optional item objectives.

Quests are turned in at a designated NPC (`turn_in_npc` field). Quest progress (SLAYER/COLLECT counts) persists across deaths via GameState's story_flags.

---

## 15. Map

Full-screen world map overlay toggled with M. Room rectangles colored by section (coast = sea-green, sprekken = dungeon-purple, etc.), with fog-of-war for unvisited rooms. Reveals are driven by `map_section_revealed` signals and persisted in story_flags.

The map is a pure renderer — it reads the scene graph built by PathManager and draws room positions. No layout decisions happen in the map code.

## 16. HUD

The HUD (CanvasLayer autoload) displays:

- **Health bar** — current/max HP with numeric label
- **Noise bar** — current noise level
- **Smell bar** — current smell level
- **Status strip** — colored squares for each active status effect, tinted to the effect's color, showing the display name initial
- **Weapon slots** — active primary/secondary and prepared primary/secondary
- **Boss bar** — appears during boss fights with boss name, HP bar, phase label, and stagger meter
- **Floating damage numbers** — world-space damage popups on hit
- **Toast messages** — temporary notifications (quest progress, item pickups, kenning unlocks)

## 18. Autoloads

The game uses an autoload-heavy architecture. All singletons:

| Autoload | Purpose |
|---|---|
| EventBus | Global signal hub — emitters and listeners connect here without direct references |
| GameState | Persistent data: souls, deaths, story flags, kenning loadout, arch state |
| RunState | Per-run data: inventory, equipment, runes, HP, weapon slots |
| PathManager | World layout: pool scanning, chain generation, scene graph |
| KenningManager | Kenning catalog: unlock tracking, loadout management, aggregate stat queries |
| QuestManager | Quest tracking: active quests, completion checks, turn-in logic |
| SaveManager | Three-slot save/load orchestration |
| CraftingUI | Crafting interface overlay |
| InventoryUI | Inventory interface overlay |
| DialogueUI | Dialogue interface overlay |
| HUD | Health/noise/smell bars, status strip, boss bar, damage numbers |
| Toast | Temporary notification messages |
| WorldMap | Full-screen map overlay |
| DifficultySettings | Difficulty profiles and multiplier getters |
| CraftingRegistry | Recipe lookup by output item |

## 19. File Conventions

### Scene naming

Region scenes follow the pattern `{pool_prefix}_{type}_{number}.tscn`:
- `buffer` — 2-exit corridor (entry + forward)
- `cross` — 3 or 4-exit intersection
- `clearing` — 1-exit dead-end (reward room)

Exit nodes are named `ExitNorth`, `ExitSouth`, `ExitEast`, `ExitWest`.

### Resource naming

- Items: `res://items/instances/{snake_case}.tres`
- Weapons: `res://weapons/instances/player_weapons/{snake_case}.tres` or `enemy_weapons/{snake_case}.tres`
- Status effects: `res://status/instances/{snake_case}.tres`
- Runes: `res://items/runestones/{letter}_{conduit}.tres`
- Kennings: `res://kennings/instances/{snake_case}.tres`
- Recipes: `res://crafting/instances/{action}_{item}.tres`
- Quests: `res://quests/instances/{quest_id}.tres`

### Sprite sheets

- Enemies/bosses: 256×192 (3 rows × 4 columns, chibi pixel art)
- NPCs: 256×64 strips (1 row × 4 columns)
- Shader: `combat_tint.gdshader` with lerp blending for hit flash
